# Fix the serial feature-miss bottleneck

Date: 2026-09-21. **Decision: parallel prewarm at the existing ordered pool's miss barrier, then retry the missing maps.** This is option (a) integrated into the current loader, without a separate corpus scan or CLI.

## Evidence and scope

The measured profile supersedes the earlier warm-cache premise: `load_map_all` takes about 6.4 seconds/directory, 86% in `audio_features` on misses; roughly half the 874 train representatives miss the shipped 1116-key cache. Approximately 437 × 6 seconds = 43.7 minutes of serial feature work. Enumeration, held-out checks and the approximately six seconds of total content hashing are negligible. A small cache file does not establish a high hit rate on the current representative/grid set.

The earlier plan's parent-only feature computation was the wrong restriction for this workload. The implementation confirms the mechanism: `OrderedMapPool.map` collects misses, then calls `groom.load_map_all` for each in the parent, invoking both serial librosa and repeated cache writes. Replace that branch; do not optimize hashing, change representatives, shrink grids or remove HPSS.

Alternatives considered: allowing each map worker to compute opportunistically is shorter locally but duplicates expensive work for shared keys and makes first-key ownership depend on scheduling. A standalone prewarm CLI duplicates discovery and adds another user step. Use the existing miss discovery plus one deduplicated feature-job phase instead.

## Contract

- Preserve `groom.audio_features`, `_feat_key`, `FEAT_VERSION=2`, sample order, filtering, weights and training/decode math exactly. Full unrounded grids go to feature computation; only the existing key function performs rounding.
- Existing `prepare --dataset-cache --loader-workers auto` opts in. `--loader-workers 1` and omitted flags retain the serial path. No new flag, dependency, GPU work, retraining or A/B decode.
- Workers may compute and return feature tensors; only the parent may publish the run-local cache. Never modify shipped caches, models, corpus inputs or completed prepared artifacts.
- Use the existing spawned pool, auto cap of eight workers and child numerical thread budget of one. Do not change the parent's numerical environment. Bitwise equality is an acceptance requirement on this environment, not an untested universal claim about every librosa build.

## Minimal flow change

1. Retain ordered map discovery. `_worker` returns a structured miss with directory ordinal, audio path, full step grid and `_feat_key`, using the existing `FeatureMiss` payload. No second parser or metadata-only approximation. Successful maps keep their existing result slots.
2. The parent checks every miss against its authoritative run-cache dictionary, including feature deltas from earlier `.map()` calls. This matters because one pool serves train followed by val while child snapshots can be stale. A valid parent hit needs only a map retry, never another feature computation.
3. Deduplicate genuinely missing keys in first-directory order. The first canonical request supplies audio/grid when aliases share a key, exactly as serial caching does. A wrong-length value is a miss/replacement under the current rule. Never use completion order as cache precedence. Conflicting request lengths for the same key abort explicitly rather than changing cache identity semantics.
4. Submit one top-level feature job per unique miss to the same spawned executor. Each calls the unchanged `groom.audio_features(path, full_grid)` directly, **not** `cached_audio_features`. Return key, CPU tensor and elapsed time/PID. Bound outstanding feature jobs/results to at most `2*workers`; no nested pool. Keep ordinary feature errors distinct from broken-process/transport failures.
5. Validate returned key, CPU placement, dtype and shape against the existing feature output (`float32`, `[len(grid), N_AUDIO]`). Merge results into parent memory in canonical first-request order, preserving untouched entries and replacing invalid-length entries. Never round/recast feature values to make tests pass.
6. Retry only missing maps on the same workers, supplying each task the relevant resolved key/tensor explicitly. The read-only provider for that retry must prefer the supplied tensor over its stale snapshot. Do not rely on a previous task having warmed the particular worker selected next. A second miss is a failure, not a fallback to serial feature computation. Final result slots, chart dictionary order and parent family-weight assembly remain unchanged.
7. Publish the merged run cache **once after successful train+val loading**, on normal pool-context exit, using a same-directory temporary file plus atomic replace. Publish no cache update on failure; preserve the original run cache. No write at all if no entries changed. Update the parent's `groom._FEATS` view consistently, so later consumers cannot overwrite the warmed file from stale memory. Prepared-dataset identity is constructed only after this publication.

For an ordinary audio decoding failure, retain the existing map-exclusion outcome and log the affected directory/reason; do not substitute zeros. A failure must not become a negative cache entry that hides a later successful alias: retry subsequent aliases for that key in canonical order if necessary, retaining earlier failures as exclusions. Transport/worker crashes fail preparation and publish no dataset completion marker. Tests pin these distinctions; the successful corpus path remains one computation per unique missing key.

The cache persists at `RUN/feats_cache.pt` and prepared rows at the existing dataset path. `train --use-prepared-dataset` performs no feature work. A subsequent loader using this warmed run cache performs zero feature computations. A fresh run seeded from the old shipped cache is cold again; this packet does not create a shared cross-run cache or silently promote a run cache to production.

## Acceptance and bounded evidence

Use the supplied profile; no new discovery profiling, full cold serial rebuild, S/P/P/S benchmark or checkpoint rehearsal. Existing mathematical functions and trainer are unchanged. Targeted implementation checks:

- Construction-known tests exercise out-of-order completion, duplicate keys, train-to-val stale worker snapshots, invalid lengths, all-hit/all-miss inputs, worker errors, ordinary audio failures, atomic publication failure and warm reuse. Assert zero parent `audio_features` calls and zero worker shared-cache writes. Compare complete seven-field ordered dataset payloads and split RNG state, including existing post-CROP family-weight behavior, against the serial path.
- Real feature gate: freeze up to 16 unique misses in canonical order before executing feature jobs, spread evenly over the miss list rather than selecting easy clips. Compare serial `audio_features` with worker results byte-for-byte on full production grids; include several initially cached requests with their entries removed in a private fixture cache. No `allclose`. Record exact keys, input hashes, versions and tested thread settings. This bounded check tests the numerical premise; it does not claim independent serial recomputation of every corpus feature.
- If an existing serial-warmed run cache or saved serial dataset from the regression is available, use it as an additional reference only after binding matching audio/grid/version/source identities. Compare all covered new features and dataset rows exactly; report independent reference coverage. Do not compute an additional 44-minute cold serial reference just to increase that coverage.
- On one corrected full clean train+val prepare, freeze the starting cache hash/count and record discovery, unique misses, feature job durations, maximum active jobs, merge/retry time and total elapsed. Preserve every successful computed feature for actual use. Target **<=10 minutes total prepare on this box with approximately the stated workload**, and require **>=4x feature-stage throughput** versus the sum of the same run's individual feature-job elapsed times. The latter is a concurrency ratio, explicitly not a freshly measured serial speedup. The ideal 44/8≈5.5-minute feature stage is a projection, not a promise; startup, I/O, parse/retry and persistence add time.
- Then load the full dataset serially from that warmed run cache, without feature computation, and compare canonical dataset bytes and split RNG state to the parallel prepare. This proves full-corpus assembly equivalence; it is **not** an independent full-corpus feature-math check. Reuse the prepared dataset through its existing branch and confirm the same digest. No full training required.

Accept only if the applicable exactness tests pass, persistence is verified, no parent serial fallback occurs, and the time/throughput gates pass. A bit mismatch rejects parallel feature computation; diagnose the failing key without altering feature math or relaxing equality. A missed speed gate is reported with the already-collected stage times, not another tuning sweep. Production defaults stay unchanged regardless. Report tested coverage and actual times; do not call the target achieved from the 44/8 estimate.

This correction supersedes the parent-only feature sections and old performance-measurement schedule in the [original speed design](2026-09-21-pipeline-speed-design.md). It does not reopen unrelated cache-identity, model-quality or decoder work. Resume the clean-rhythm pilot with accepted opt-in loading after the packet.
